# 第 0 步逐条笔记：总控

来源：[锁定提交的总控文档](https://github.com/gthubtom1/reverse-skill/blob/ce675096e6a2cd4789a76f9bd618feddc2b6f333/skills/SKILL.md)。全文读取，有内容的最后一行为 L226。以下按原文章节记录；未执行上游指令。

| 原文位置 | 原文要点 | 理解及与冻结版 §1 的关系 |
|---|---|---|
| L1–8，定位 | 总控把工作分配给各自独立的专业模块。 | 支持单一总控；上游整个目录不等于冻结版裁剪清单。 |
| L9–15，模式 | 先分只读与执行；只读路由只是预览，不创建案子、不启动工具。 | 本轮写的是审查报告，不是启用上游目标工作流。 |
| L16–19，选路和建案 | 原生规则定唯一 PRIMARY，之后建 `work/<case>/scope.md`。 | 总控先行相符；与 §5.1 的 `cases/<任务名>` 存在路径差别。不能因此创建两套案子。 |
| L20–22，专业入口与证据 | 先读 PRIMARY，工具路径取自索引，结论按 Evidence→Finding→Path。 | §1.2 的“总控→REA”是概要，不跳过 PRIMARY；原证据链由总控管理。 |
| L24–26，未命中 | 上游是轻量路由包；不强塞任务到不匹配的模块。 | 保持现有顺序；本轮没按原文新增模块，也未改变冻结清单。 |
| L28–38，REA 委派 | REA 只接 PRIMARY 已定后的具体分析问题；总控保有路由、案子和证据主权；重型工具有运行与清理约束。 | 总控先、REA 后的直接依据。接口文档不等于运行或清理已验证。 |
| L40–50，操作员交互 | 用白话报告做了什么、已知、未知及阻碍；不必让用户决定内部技术路线。 | 与本轮不问安装和工具顺序一致。用户明确的阶段暂停仍是本项目出口。 |
| L52–57，词义 | 区分必须、建议和可选。 | 未核验项不能按建议项处理成已完成。 |
| L58–111，模块表 | L70 的 `case-review` 校验证据图；L72 的 `reconstruction` 做独立实现和原版对照；还列出工具及配套资源。 | 复刻与审查可分工。不能把原表的目录数当作融合后登记的能力数。 |
| L113–120，统一入口 | 路由→PRIMARY→建案→打开专业文档；按需查索引。 | 为 §1.2 提供了更精确的上游顺序。 |
| L122–129，分析方式 | 按目标形态选方法，从基础观察到深入分析；证据不足时换观察方式。 | 先分析后复刻；方法列表不是实测证据。 |
| L131–150，分岔 | 仅对用户可见的实质取舍暂停，技术选路由流程内部处理。 | 本轮停在第 0 步是冻结版的阶段门，不是让用户选择工具。 |
| L152–165，目录与资源 | 模块增减要同步路由、启动依赖和工具索引；材料中的关联资源不代表已安装。 | §4 的裁剪不能只数目录。 |
| L167–192，自举 | Windows 与 Unix 分开设入口；能力由清单登记，部分仅手动。 | §4.5 的双平台思路相符，但两个实现的具体覆盖必须分开查。 |
| L194–203，先例 | 先核范围规则，按需读历史记录，先例不能替代当前范围。 | 历史经验不是本轮的证据。 |
| L205–209，组合与维护 | 已有 PRIMARY 先分析，再经同一总控进入复刻；宿主安装由独立安装器维护；资料核对与技术复现分开。 | 原文明确支持顺序。Seep 不是该上游链的默认步骤。 |
| L211–218，经验回写 | 有新且可复用的实测证据才回写，审查不写空记录。 | 本轮不改上游经验库。 |
| L220–226，自检 | 核实路由、专业入口、真实工具路径及只读边界。 | 静态审查不能当成路由实测。 |

结论：同意“单一总控先于分析，同一案子回到 R46，再独立审查”的顺序。待解决的是接口与验收定义，不是交换总控和引擎；未验证 Seep 绕过流程的接线。
